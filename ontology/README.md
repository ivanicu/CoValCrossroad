# The typed normative record — an input and its output, NOT two versions of one file

`DESIGN_mine.md` and `RECONCILED_three_designs.md` sat side by side in the repo root as
`ONTOLOGY.md` and `ONTOLOGY_RECONCILED.md`, and they read like a file and its newer copy.
**They are not.** Under the triple-blind rule (`realstat §2.5`) `DESIGN_mine.md` is *one of three
independent designs*; `RECONCILED_three_designs.md` is the merge of all three, and it records that
one design's central objection was checkable and that checking it produced that day's sharpest
result.

**So the older file may not be deleted or folded in.** Deleting the input destroys the only
evidence that the output was a reconciliation rather than a first draft — and the whole value of
triple-blind is that the disagreement is the finding. They are grouped here so the relationship is
visible, and that is the most that should be done to them.
