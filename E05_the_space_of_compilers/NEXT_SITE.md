## Three requirements this site can already specify precisely

1. **A second core in the same release.** The whole *"the definition describes the instance"* risk
   reduces to this: the extension is **[0, 1]** and its single member is the object the definition was
   written from. **One more released core would make the extension question a measurement.**
2. **A cross-space key.** The rubric and ranking id spaces are disjoint; the join had to be recovered
   from criterion texts (**968 of 968**, validated on a different channel). **A shipped key removes an
   entire class of round.**
3. **Construction provenance shipped with each object.** ③ is a **provenance** predicate: a reader
   handed a criterion set can check ①②④ and not ③, and two behaviourally identical sets differ under
   it. **Ship how each set was built, or ③ is permanently unverifiable.**

## What this specification does not cover

**54 register entries name no requirement.** They fall into three kinds, and only the first is a real
gap:

- **unavailability without a remedy** — *"construct validity of `chosen` — the release's own human
  choice"*. A requirement is implied and was never written. **These are the ones to fix.**
- **scope statements mislabelled as impossibilities** — *"a clause that excludes the length rule — a
  category error: it is outside the domain"*. Nothing is missing; the entry is in the wrong section.
- **restatements** — *"the supremum over criterion-free rules — R435's 30-member family, restated"*.

⚠ **The 54 is a lower bound on the work, not a defect count**: the classifier tests **phrasing**, not
**content**, so an entry naming a requirement in words the pattern misses is counted against the
register. The tested figure is **35 explicit**; **46** is the generous reading.
