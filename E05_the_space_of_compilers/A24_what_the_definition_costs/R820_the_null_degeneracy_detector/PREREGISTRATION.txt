R820 · THE NULL-DEGENERACY DETECTOR, VALIDATED AGAINST TEN LABELLED CASES
written before the run · this is a PRODUCTION action with a validation experiment attached

PROVOCATION
R819 counted five degenerate negative controls in this session and proposed a gate: run each
declared null twice at different seeds, fail when the spread is zero or the null's centre equals the
observation. It claimed four of the five would have been stopped before the round shipped.

⛔ CHECK #422 FOUND THE ARCHITECTURAL PROBLEM FIRST. **The committed artifacts do not contain the
degenerate nulls.** Each was repaired before anything was written, so every `results/*.json` holds
the REPAIRED value; only 9 recent rounds record a null field at all, under six inconsistent names
(`null_lo/hi`, `null_mean/max`, `null_sd`, `null_spearman`, `null_floor`, `label_null`). A gate that
runs at commit time, like the existing seven, is STRUCTURALLY BLIND to this class: it sees only what
survived. So the detector cannot be retrospective — it has to be a runtime assertion a round calls.

⭐ BUT THE BROKEN VALUES ARE COMMITTED, in `RETRACTIONS.md` entries 1214, 1217, 1226, 1234 and 1244.
That gives a labelled validation set: five known-BROKEN nulls and their five known-REPAIRED
counterparts.

ESTIMAND
E1  the detector's two candidate rules, each with a threshold:
      R1 ZERO SPREAD    — the null's spread is below eps
      R2 OVERSHOOT      — |null centre| exceeds |observation|
E2  ⭐ validation on the ten labelled cases: how many BROKEN fire, how many REPAIRED falsely fire.
E3  ⭐ the threshold sweep for R1: eps from 0 to 1e-2, reporting where separation holds and breaks.
E4  the installed artifact: a runtime assertion rounds call, plus what it costs to call it.

IDENTIFICATION
The ten cases are TRANSCRIBED BY HAND from committed files, which realstat §4 warns against — "a
control validated only against cases you invented is validated against your imagination". The
mitigation is mechanical: **every transcribed value must be verified to appear LITERALLY in the file
it cites**, and a case whose value cannot be found is dropped and counted. That check is a positive
control on my own transcription and runs before any rule is evaluated.
⚠ n = 10 is small and the round claims no rate beyond this set.

DERIVED BEFORE MEASURING
D1 [DERIVATION] R2 cannot separate R816 from R819's REPAIRED control. R816's bad null was −0.870
   against an observation of −0.553; R819's GOOD repaired null was +1.1439 against +0.0617. Both
   have |null| > |observation|, same sign, observation between zero and null. **So R2 is predicted
   to false-positive on a passing control**, and if it does the rule is unusable — stated before
   the run so that its failure is a result and not a surprise.
D2 [DERIVATION] a null with spread exactly 0 destroyed nothing, whatever its centre. R1 needs no
   reference to the observation, which makes it the cheaper and more robust rule.
D3 R813's repaired null (0.0097 ± 0.0007 against a real 0.0099) is the HARD case: it passed, but
   weakly, and its centre is within one sd of the observation. A rule keyed on "centre equals
   observation" would flag it. It is in the set precisely because it is near the boundary.
D4 the detector is an instrument; a rule that fires on every case is as useless as one that fires on
   none, so both error directions are counted.

WORLDS
A  R1 SEPARATES: it fires on 4 of 5 broken and 0 of 5 repaired -> install R1, drop R2.
B  NEITHER SEPARATES: R1 also false-positives -> the zero-spread signature is not the right one and
   the round says what would be.
C  BOTH SEPARATE: R2 does not false-positive on R819 -> D1 was wrong and both rules install.
CHECKED FIRST: B, because it kills the proposal outright.

PREDICTION MATRIX
                       A              B              C
R1 broken fired      4/5            any            4/5
R1 repaired fired    0/5            >0             0/5
R2 repaired fired    >=1 (D1)       any            0/5

CONTROLS
OBJECT   every one of the ten transcribed values must be found LITERALLY in the file it cites
         (RETRACTIONS.md or the round's README). Exit 2 if any is missing.
PLACEBO  a null with genuine spread centred on zero must NOT fire either rule.
POSITIVE a synthetic dose ladder on spread: sd in {0, 1e-9, 1e-6, 1e-3, 1e-2}; R1 must fire below
         its threshold and not above, and at sd=0 it must always fire.
NEGATIVE a null drawn from a real permutation with genuine spread must not fire — using R819's own
         repaired six-member null as the case.
NOISE FLOOR the detector is deterministic given its inputs; the round states this rather than
         inventing a spread for it.

PRE-REGISTERED KILL -- conditional, never a bare threshold
  if all_ten_values_verified and placebo_silent and positive_ladder_monotone:
      if R1 fires on >=4 broken and 0 repaired   -> WORLD A (install R1; R2's fate reported)
      elif R1 fires on any repaired               -> WORLD B
      else                                         -> WORLD C
  else:
      UNVERIFIED   (never OVERTURNED, never CONFIRMED)

MULTIPLICITY 2 rules x 10 cases reported in full; no case is dropped for its result, only for a
failed transcription check, and that count is printed.
STOPPING RULE one round. If the detector installs, it is written to `assurance/` in the same commit
as the round that validated it, never deferred.
