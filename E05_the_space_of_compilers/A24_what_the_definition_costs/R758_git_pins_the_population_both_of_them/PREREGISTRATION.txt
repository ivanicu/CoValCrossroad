--------------------------------------------------------------------------------
⛔ THE ARITHMETIC, DERIVED BEFORE MEASURING
--------------------------------------------------------------------------------
FORCED, labelled, not evidence:
  - a larger corpus can only lower a flagged rate, and a longer document can move it either way.
    So if the pinned rate is HIGHER than today's, the document is the cause; if LOWER, both are
    candidates. The SIGN of the difference is diagnostic and is read that way.
  - R756's variance ratio has the newly-resolved rounds entering with LOWER flagged rates, which
    lowers the pooled mean. Variance is not monotone in the mean, so the ratio is NOT forced in
    either direction -- which is why P4 is registered rather than derived.
  - reproducing a number from a pinned tree is a CONSISTENCY check, not a validity check. It shows
    the pipeline is deterministic given its inputs; it says nothing about whether the numbers mean
    what they were said to mean.

STRONGEST CONFOUND, written BEFORE the run: an artifact may have been EDITED IN PLACE after being
committed, in which case the historical corpus and the historical document both reproduce and the
rate still differs -- and the cause would be invisible to a tree comparison. CONTROL IN THE SAME
ITERATION: compare each A24 artifact's blob hash at R753's commit against HEAD and report how many
differ. That distinguishes "files were added" from "files were changed".

--------------------------------------------------------------------------------
CONTROLS
--------------------------------------------------------------------------------
POSITIVE   the recovered `DEFINITION.md` must be SHORTER than today's by exactly the 198 lines the
           git comparison showed, and `FORMULATION.md` must be byte-identical. BAND, COMPUTED: a
           recovery that returns today's file gives delta 0 for all three (the failure my first
           lookup produced); a recovery that returns nothing gives an empty file. The measured
           deltas must be strictly between -- i.e. two documents differ and one does not.
g=0        recovering HEAD's own tree and recomputing must reproduce TODAY's rates exactly. If it
           does not, the recovery path itself is lossy and every historical number it produces is
           suspect.
NEGATIVE   compute R753's rates using the historical DOCUMENTS but TODAY's corpus, and using today's
           documents with the HISTORICAL corpus. Both crossed cells must be reported. If either
           crossed cell reproduces R753 exactly, then only ONE population mattered and the other is
           not part of the explanation.
SHAM       the same operation with the INGREDIENT ABSENT, not inverted. Ingredient = the historical
           tree. Recompute using a DIFFERENT commit's trees -- R750's, which is further back -- and
           report whether R753's rates reproduce there too. If they do, reproduction is not evidence
           that the pinning is correct, because any old tree would serve.
PLACEBO    recovering the same tree twice must give byte-identical documents, 0 of 3 differing.
NOISE      no rng anywhere in this round; every quantity is a deterministic function of two trees.
UNIT       instrument unit = a (figure, corpus-version, document-version) triple; claim unit = a
           published RATE. Not equal -- a rate aggregates figures -- so the triple counts are printed
           beside every rate rather than folded into it.
