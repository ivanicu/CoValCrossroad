WHY THIS ROUND EXISTS
--------------------------------------------------------------------------------
R759 closed the provenance sub-arc and pointed back at the object, proposing that the 7 target-reading
tags be resolved to objects.

⛔ CHECK #362 KILLS THAT: R730's committed artifact already records `objects_of_the_seven` as FOUR
classes, and `r729_seven_tags` as exactly those seven. I read that field in R747. So the proposed
round is prior art -- the FIFTH rebuild the gate has stopped in this arc, and the first one I proposed

WHAT IS ACTUALLY OPEN. Clause ③ is implemented as FOUR LITERAL ARM NAMES:

    USES_PROMPT_LABELS = {"oracle_k4", "oracle_k4_fit1", "greedy_k4_fit1", "indep_k4_fit1"}

R520 and R729 established it is a BLOCKLIST and therefore FAILS OPEN. R745 measured the consequence
on today's population: the census admits THREE target-reading objects that ③ is supposed to exclude.
Meanwhile the builder's own source names the target-reading rules exactly, at select_core.py:102 --
`if a.rule in ("oracle_k", "indep_k", "greedy_k"):` loads the human target.

So ③ could be implemented BY RULE rather than BY NAME. Nobody has priced that.

⚠ P4, RUN ON BOTH QUESTIONS. R509 tested replacing ③ (provenance) with ③′ (a BEHAVIOURAL test --
"not optimised against the labels") and concluded DO NOT: "it makes the same vacuity harder to see."
R623 is about a documentation-anchoring rule, a different object. A RULE-BASED PROVENANCE ③ is
neither of those: it keeps ③'s type (provenance) and changes only its implementation (rule, not
list). That is the gap.

--------------------------------------------------------------------------------
⛔ THE ARITHMETIC, DERIVED BEFORE MEASURING -- TWO RESULTS ARE FORCED
--------------------------------------------------------------------------------
D1  THE RULE SET IS A SUPERSET OF THE BLOCKLIST. All four blocklisted names carry a target-reading
    prefix, so rule-③ excludes AT LEAST what name-③ excludes. "It excludes more" is ALGEBRA. Only
    the SIZE of the excess is a measurement, and it is asserted in code rather than assumed.
D2  THE COMMITTED EXTENSION IS INVARIANT. None of `coval_core`, `topw_k3`, `topw_k4`, `topw_k6`,
    `topw_k8` carries a target-reading prefix, so a stricter ③ cannot remove any of them. The
    extension stays at 5 on the committed 41 BY CONSTRUCTION. World C therefore cannot fire on the
    committed population -- only on today's wider one -- and that asymmetry is stated rather than
    discovered.

So the round's real content is E1's SIZE, E2's object count, and E3's vacuity check.

STRONGEST CONFOUND, written BEFORE the run: an arm may READ the target without its rule saying so --
a hand-built arm, or one whose tag_suffix hides its provenance. Then rule-③ under-excludes for a
reason invisible to the grammar, exactly as the blocklist under-excludes for a reason invisible to a
list. CONTROL IN THE SAME ITERATION: report the count of UNPARSED tags in the population and name
them, so the rule's own blind spot is sized rather than assumed empty.

--------------------------------------------------------------------------------
CONTROLS
--------------------------------------------------------------------------------
PROVENANCE the three source facts are asserted against corebench/select_core.py at runtime -- the
           closed nine-rule vocabulary, the target-reading line at :102, the tag emitted from the
           rule at :204. The round EXITS 2 if the builder does not carry them, because the whole
           instrument rests on the tag being rule-derived.
POSITIVE   `oracle_k4_oracle_kA` is target-reading by its rule prefix and is NOT in the blocklist --
           it is one of the three objects R745 found admitted. Rule-③ must EXCLUDE it. And `topw_k4`
           is a selector and must NOT be excluded. BAND, COMPUTED: floor = a ③ that excludes nothing
           (0 exclusions on a known target-reading arm), ceiling = a ③ that excludes everything
           (which would also exclude `topw_k4`). The threshold is "excludes the first and not the
           second", unreachable from either degenerate end, asserted in code.
g=0        an UNPARSED tag must be reported and counted, never silently admitted (which would let a
           hidden target-reader through) nor silently blocked (which would inflate the repair).
NEGATIVE   invert the rule set -- block the SELECTOR families instead of the target-reading ones --
           and confirm the admitted set changes. World excluded: "③ makes no difference whatever it
           blocks", which would mean ② alone determines everything and ③ is decoration.
SHAM       the same operation with the INGREDIENT ABSENT, not inverted. Ingredient = the RULE. Block
           a RANDOM set of four arm names, size-matched to the blocklist, over 5 seeds, and report
           what that does to the admitted set. A principled ③ must differ from an arbitrary list of
           the same size; if it does not, the blocklist's content was never doing the work.
PLACEBO    running name-③ must reproduce R728's committed 16 admitted tags exactly. If it does not,
           the harness is not the census and nothing below is comparable.
NOISE      no rng except the SHAM's random blocklists, seeded, 5 draws, spread printed.
UNIT       instrument unit = an ARM TAG; claim unit = an OBJECT (R730's partition). NOT equal -- R730
           measured 7 tags as 4 objects -- so every count is reported in BOTH and never conflated.
