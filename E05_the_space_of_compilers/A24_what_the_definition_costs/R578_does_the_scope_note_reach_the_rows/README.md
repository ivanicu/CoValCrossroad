# R578 · The scope note did not reach the row it conditions

**Decision this makes safe:** how a scope correction lands on a claim table.

**Measured:** of 10 claim rows, **1 states an extension count** (row 2: ③-rank **5**, ③-any **0**,
③-judge **0**) — the exact quantity R558 showed is **target-conditional**, since at `A1` the
extension is **∅**. **Rows naming the target anywhere in claim or scope: 0.**

**R558 fixed this with one note above the table.** The note is correct and it sits **~40 lines
above** the row. **A reader of row 2 alone sees an unconditional count.**

## ⭐⭐⭐ Two laws in tension, resolved by a pointer
- **P16:** one home per fact — *a number stated twice drifts, and the copy is never the one fixed.*
- **The correction law:** a correction must **reach the artifact** it conditions, not sit in
  frontmatter.

**A copy violates the first. Silence violates the second. A MARKER violates neither** — the row
carries `†`, the table carries the fact, and there is still exactly one home.

**Landed:** row 2's three counts now read `5†`, `0†`, `0†` with the condition named inline in nine
words, and the scope table states that `†` resolves there.

## Controls
- **The instrument is its own control**: it found **1** conditioned row out of 10 and **0** rows
  naming the target — a discriminating result, not a uniform one. *(R575's lesson: uniform output
  across a population is the signature of a dead instrument.)*
