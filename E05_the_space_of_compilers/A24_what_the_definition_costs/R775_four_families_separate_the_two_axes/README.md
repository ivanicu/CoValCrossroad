target-reading family's scale may be compressed because its members all read the same labels."*

## ⚠ and my axis null is nearly vacuous — D3 was right and not right enough

The axis difference is **+0.3544** against a permutation interval of **[−0.2117, +0.3544]** — the
observed value **is** the interval's upper end. **With four families there are only four ways to label
one of them "target-reading", so the permutation has 4 outcomes and the observed labeling is one of
them**; a p-value from it cannot go below 1/4. D3 correctly said the six correlations are not six
independent numbers, and then built a null whose resolution I did not check *(ledger 1108)*.

## NEXT

The rule gradient is the finding and it rests on **one** same-rule pair. The release ships enough
`random_k` arms to build a **third** same-rule family (`random_k2_s1`, `random_k3_s1`, `random_k6_s1`,
`random_k8_s1`, `random_k12_s1` — same rule, different seeds, disjoint from F2 and F4 at the object
level), which turns *"same rule correlates at 0.72"* from a single number into **three** same-rule
pairs against **six** different-rule ones. ⚠ And it fixes the vacuous null in the same move: six
families give **2⁶ − 2 = 62** labelings rather than 4, so the axis test acquires resolution it
structurally lacked here. The registered quantity is the same relative-correlation matrix over six
disjoint families, with the same-rule and different-rule blocks compared against a permutation null
that can actually resolve them.
