R811 · SOURCE OR RULE — what is a core's advantage actually made of, at matched k?
written before the run · NBOOT 1200 · ZEFF 2.801585

PROVOCATION
R810 asked whether `topw_k`'s advantage over `POOL[0:k]` is resolved at matched k, to decide whether
clause (2) names one baseline or two. CHECK #413 read R810's own table first: that gap is
NON-MONOTONE -- +0.0018, +0.0121, +0.0238, +0.0046 at k = 2,4,8,12 -- and the comparison confounds
TWO things, because `topw_k` draws from the PROMPT'S OWN RUBRIC while `POOL[0:k]` draws from a FIXED
GENERIC SET. Source and rule are tangled in a single number.

The third arm already on disk decomposes it: `random_k` is the prompt's own rubric under an
UNINFORMATIVE rule, and R810 measured it at 0.4807 / 0.4920 / 0.5066 / 0.5154 -- far BELOW the
generic pool at every k. So a random subset of a prompt's own rubric loses to a fixed generic list.

⛔ AND A SECOND DEFECT IN R810's BASELINE, WHICH IS MINE. `POOL[0:k]` is ONE ARBITRARY SUBSET of the
16 -- the first k in file order -- and R810 (and earlier rounds) used it as THE blind baseline. That
is the "one draw quoted as the cell" shape. The pool is a FIXED generic set of 16 identical across
prompts (verified: 1 distinct criterion-list over 50 prompts), so the uninformative-rule cell is the
DISTRIBUTION over k-subsets of 16, and the first-k is a single draw from it whose percentile is
measurable.

ESTIMAND
E1  a 2x2 at each k in {2,4,8,12}:  SOURCE {prompt rubric, generic pool} x RULE {uninformative,
    informative}.  ⚠ ONE CELL IS STRUCTURALLY ABSENT -- the pool carries no per-prompt importance
    scores, so "pool x informative" cannot be built here. Named, not silently dropped.
E2  ⭐ the RULE effect within the rubric: topw_k - random_k, at matched k.
    ⭐ the SOURCE effect at matched uninformative rule: pool-random-subset - random_k.
E3  ⭐ is `POOL[0:k]` TYPICAL? Its percentile within the distribution of random k-subsets of the 16
    -- exact where C(16,k) is enumerable, sampled otherwise, with which is stated per k.
E4  R810's NEXT answered directly: topw_k - POOL[0:k] with a CI at every k.

IDENTIFICATION
E1/E2/E4 identified at matched k on prompts attaining nominal k. E3 exact at k=2 (C(16,2)=120),
k=4 (1820) and k=12 (1820); SAMPLED at k=8 (12870 -- still enumerable, so it is enumerated and the
count is printed).
⚠ AMENDED BEFORE THE RUN, and the amendment is stamped rather than hidden: the paragraph here
first claimed `random_k` has only s0 at k=12. The inventory run one command later shows s0, s1 AND
s2 at k = 2,4,8,12. The false statement was written from memory of an earlier `ls` that had been
truncated. All four k therefore carry THREE seeds and the seed spread is measured at every k. Left
in the record because a preregistration that quietly self-corrects is not a preregistration.

DERIVED BEFORE MEASURING
D1 [DERIVATION] at k = n both rules select everything, so the RULE effect must vanish as k -> n.
   A decreasing rule effect is therefore partly forced; the question is its size at reachable k.
D2 [DERIVATION] the pool's uninformative cell has no per-prompt variation in WHICH criteria are
   available, so its subset distribution is the same 16 for every prompt -- the spread across
   subsets is a property of the 16, not of the prompts.
D3 the pool is prompt-blind, so any advantage it holds over the rubric at matched rule is evidence
   AGAINST prompt-specificity being valuable, which is the opposite of what clause (2) assumes.
D4 R810's non-monotone topw-minus-pool gap should decompose into two monotone-ish pieces; if it
   does not, the decomposition is not the right one and the round says so.

WORLDS
A  RULE dominates: within the rubric, informative selection buys much more than the source does ->
   clause (2) names the uninformative baseline and "informative selection" is the ingredient.
B  SOURCE dominates: the generic pool beats the rubric at matched rule -> prompt-specificity is a
   liability and clause (2) names the blind pool.
C  COMPARABLE: neither dominates -> clause (2) needs BOTH baselines, and R810's question is
   answered "two, not one".
CHECKED FIRST: C, because it is the answer that makes the definition more expensive.

clause (2) baselines one                 one                 two
