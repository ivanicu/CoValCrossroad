R788 · `generic` is a MEMBER of its own comparator class, and the leave-one-out cannot see it
WRITTEN BEFORE ANY CODE FOR THIS ROUND. 2026-08-06.

--------------------------------------------------------------------------------
WHY THIS ROUND EXISTS
--------------------------------------------------------------------------------
R787's NEXT asked what drives the per-reference sd that makes `q_resolved` more than A2's percentile.
CHECK #390 derived it first: `Var(v − REF_i) = Var(v) + Var(REF_i) − 2·Cov(v, REF_i)`, so the sd is
LOW when an arm tracks the reference prompt-by-prompt. Then it measured the 26 arms and found the
answer is not "prompt-specificity" at all:

    arm                sd(v − REF)   corr(v, REF)   q_resolved
    topabs_k4 … shams   0.147-0.174    0.45-0.56       0.0000
    oracle/greedy/…     0.123-0.135    0.59-0.67    0.0396-1.0000
    **generic**         **0.0711**     **0.8859**      0.7780

⭐ `generic` sits at HALF everyone else's sd and far above everyone's correlation with the class. **And
the object says why: `core_generic.json`'s four criteria are pool indices [0, 1, 2, 3] — `generic` IS
`POOL[0:4]` as a SET, hence one of the C(16,4) = 1,820 references.**

⚠ AND THAT RECONCILES R782, WHICH MEASURED THEM AS DIFFERENT OBJECTS. R782 found the raw satisfactions
differ by up to 0.121 on 73 of 968 prompts and called it "different objects, below resolution". Both
are right: **the same criterion SET, scored in two different judge passes.** So the arm is compared
against a class containing its own criteria, while the leave-one-out used in R781/R782 excludes a
reference only when the per-prompt difference is identically zero — which a second judge pass makes
false. **The exclusion cannot fire.**

--------------------------------------------------------------------------------
DISCLOSURE -- what was already known when this was written
--------------------------------------------------------------------------------
The sd/corr table and the pool-index fact come from check #390 and are quoted. **E2's exact
leave-one-out count, E3's magnitude and E4's verdict impact are NOT known.** The world is gated on E3.

--------------------------------------------------------------------------------
ESTIMAND (before method)
--------------------------------------------------------------------------------
E1  the decomposition, verified rather than asserted: for each arm, `Var(v − REF)` against
    `Var(v) + Var(REF) − 2·Cov(v, REF)`. Any mismatch falsifies the algebra and the round stops.
    Claim unit = an ARM; instrument unit = an (arm, reference) pair. Named, unequal.
E2  ⭐ how many references the satisfaction-based leave-one-out excludes for `generic`, and how many a
    CRITERION-based exclusion would exclude. If the first is 0 and the second is 1, the exclusion has
    never fired for the one arm that needs it.
E3  ⭐ the MAGNITUDE: `generic`'s q and q_resolved with the self-reference excluded by CRITERIA, against
    the published values. **This is the number that decides whether the leak matters.**
E4  whether any published verdict moves: R786's counterexample rests on `generic`'s q_resolved of
    0.7780, and R782's table places it between `topw_k4` and `gen`.

--------------------------------------------------------------------------------
IDENTIFICATION
--------------------------------------------------------------------------------
E1, E2 exact.
E3 exact for the self-exclusion, but ⚠ PARTIALLY IDENTIFIED for the leak's full size: removing one
   reference of 1,820 changes q by at most 1/1820 = 0.00055 mechanically. **The leak's real effect is
   not the removal — it is that `generic`'s LOW sd, caused by resembling the class, shrinks its MDE
   and so lets it clear references resolvedly that a higher-variance arm could not.** That effect is
   identified only by a counterfactual: give `generic` another arm's sd at its own A2.
E4 exact — the verdicts are on disk.

--------------------------------------------------------------------------------
SCOPE
--------------------------------------------------------------------------------
population  R782's 26 modal-k=4 arms; the 1,820-subset class; 968 prompts
instrument  A2 per prompt over all annotators; q and q_resolved as R781/R782 computed them
baseline    the published q/q_resolved are the baseline the corrected figures are compared against
regime      first release, home judge, this tree_sha

--------------------------------------------------------------------------------
THE ARITHMETIC, DERIVED BEFORE MEASURING
--------------------------------------------------------------------------------
D1  REMOVING ONE REFERENCE OF 1,820 CANNOT MOVE q BY MORE THAN 1/1820 = 0.000549. **DERIVATION.** So
    if the leak matters it is NOT through the count, and any round that "fixes" it by excluding one
    reference has fixed nothing. Registered so the fix cannot be mistaken for the finding.
D2  A LOWER sd SHRINKS THE MDE PROPORTIONALLY: `MDE_i = ZEFF·sd_i/sqrt(P)`, so halving sd halves the
    threshold an arm must clear. `generic` at 0.0711 faces a threshold **1.87x smaller** than `gen` at
    0.1330. **DERIVATION**, and it is the mechanism the round is about.
D3  AN ARM THAT IS A CLASS MEMBER TRACKS THE CLASS, so its sd is low BECAUSE of the membership, not
    coincidentally. Cov(v, REF) is maximal for a reference built from the same criteria.
D4  THE SATISFACTION-BASED LEAVE-ONE-OUT IS THE WRONG UNIT. It matches on the OUTPUT of the judge; the
    thing that should be excluded is identity of the criterion SET, which is the INPUT. §4's
    instrument-unit-versus-claim-unit row, in the exclusion rule itself.

STRONGEST CONFOUND, written BEFORE the run: `generic`'s low sd might be a property of prompt-blind
arms generally rather than of class membership — any blind arm scores every prompt with the same
criteria and so may track the blind class. CONTROL IN THE SAME ITERATION: `genericpool16` is also
prompt-blind but is k=16 and NOT a member of the k=4 class; its sd is computed and reported beside
`generic`'s, so blindness and membership are separated rather than conflated.

--------------------------------------------------------------------------------
WORLDS
--------------------------------------------------------------------------------
A · THE LEAK IS MECHANICAL AND SMALL. Excluding the self-reference by criteria moves q by ~1/1820 and
    the counterfactual sd swap moves q_resolved little. Then the membership is a blemish to record and
    the published verdicts stand as they are.
B · THE LEAK IS THE VARIANCE ADVANTAGE AND IT IS LARGE. The counterfactual — `generic` at another
    arm's sd, same A2 — moves its q_resolved materially. Then `generic`'s 0.7780 is an artifact of
    resembling the comparator, R786's counterexample must be restated on A2 rather than q_resolved,
    and clause ②'s resolution criterion rewards similarity to its own baseline.
C · BLINDNESS, NOT MEMBERSHIP. `genericpool16` shows the same low sd despite not being in the class.
    Then the confound wins, the finding is about prompt-blind arms generally, and membership is
    incidental.

PREDICTION MATRIX
  A -> counterfactual q_resolved shift < 0.05
  B -> counterfactual shift >= 0.05 AND `genericpool16`'s sd is materially above `generic`'s
  C -> `genericpool16`'s sd is within ~10% of `generic`'s

--------------------------------------------------------------------------------
KILL -- CONDITIONAL, gated on the controls
--------------------------------------------------------------------------------
if OBJECT passes (`core_generic.json`'s criteria are pool indices, the class rebuilds to 1,820 --
   exit 2 otherwise) and E1's decomposition holds on every arm and PLACEBO fires (an arm against
   itself: sd exactly 0) and POSITIVE fires (a planted exact duplicate IS caught by the criterion-based
   exclusion and is NOT caught by the satisfaction-based one after a simulated second pass):
        counterfactual shift >= 0.05, genericpool16 sd higher  -> WORLD B
        counterfactual shift < 0.05                            -> WORLD A
        genericpool16 sd within 10% of generic's               -> WORLD C
        otherwise                                              -> report; claim no world.
else:
        UNVERIFIED. Never OVERTURNED, never CONFIRMED.

--------------------------------------------------------------------------------
CONTROLS
--------------------------------------------------------------------------------
OBJECT      `core_generic.json` ⊆ `core_genericpool16.json` with its indices printed; class = 1,820.
PLACEBO     an arm against itself: sd exactly 0 and q undefined-by-exclusion, reported as such.
POSITIVE    plant a duplicate: take POOL[0:4]'s own satisfaction vector, add a tiny jitter simulating
            a second judge pass, and require ① the CRITERION-based exclusion to catch it and ② the
            SATISFACTION-based one to miss it. BAND, COMPUTED: at jitter 0 both must catch it; at the
            observed `generic`-vs-POOL[0:4] discrepancy only the criterion rule may.
CONFOUND    `genericpool16`'s sd beside `generic`'s — blindness separated from membership.
COUNTERFACT `generic`'s q_resolved recomputed with its per-reference sd replaced by another arm's,
            holding its A2 fixed; and the reverse for `gen`. This is the estimand of E3 and it is a
            CONSTRUCTION, reported as a capability of the statistic rather than as an observation.
UNIT        instrument unit = an (arm, reference) pair; claim unit = an ARM. The exclusion rule's own
            unit is named too: it currently matches SATISFACTIONS where it should match CRITERIA.

--------------------------------------------------------------------------------
MULTIPLICITY
--------------------------------------------------------------------------------
26 arms x 1,820 references for E1 + 2 exclusion rules x `generic` + 2 counterfactual directions +
3 jitter levels for the positive + `genericpool16` for the confound. The decomposition is checked on
every arm and reported as a maximum absolute mismatch, not a rate.
