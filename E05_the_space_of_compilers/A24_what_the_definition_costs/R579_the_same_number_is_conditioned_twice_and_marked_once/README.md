# R579 · The same number is conditioned twice and was marked once

**Decision this makes safe:** what a scope marker must enumerate.

**WORLD B.** Row 2 states the only extension count on the page. Measured across all 10 rows:

| row | states an extension | names TARGET | names BASELINE |
|---|---|---|---|
| **2** | **✔** | **✔** *(added R578)* | **✘** |
| 3, 4 | ✘ | ✘ | ✔ |
| all others | ✘ | ✘ | ✘ |

**Two independent measurements condition that one number:**
- **R558** — it is **5 at `A2`** and **∅ at `A1`**.
- **R527** — it moves **4 → 8** across the `POOL[0:4]` **baseline** reference class.

**R578 added a marker for the first and stopped.** ⭐⭐⭐ **A marker is not a checkbox — it is an
enumeration, and an enumeration that stops at the first item is worse than none, because the row now
LOOKS conditioned.** A reader who sees `5†` and finds "at A2" has been told the scope is handled.

**Landed:** the `†` now names both axes and points at the scope table for each.

## Controls
- **Discriminating, not uniform**: 1 row of 10 states an extension, 2 others name a baseline without
  stating one, 7 name neither. **The instrument distinguishes four distinct states**, which is what
  R575's dead-instrument lesson requires before any verdict.
- ⚠ **Rows 3 and 4 name a baseline and state no extension** — so they are correctly scoped and appear
  in the table as the negative case.

⚠ **Not established:** whether the extension is conditioned on a **third** axis. R560 named four
G1 dimensions; **population and regime were not tested here**, and the same enumeration failure
would look identical.
