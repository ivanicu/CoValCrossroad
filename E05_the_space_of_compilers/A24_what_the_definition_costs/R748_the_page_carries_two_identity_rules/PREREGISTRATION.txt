R748 · the page carries two object counts computed under two different identity rules
WRITTEN BEFORE ANY CODE FOR THIS ROUND. 2026-08-05.

--------------------------------------------------------------------------------
WHY THIS ROUND EXISTS
--------------------------------------------------------------------------------
R747 priced one unstated parameter -- merging on SHARED prompts gives 81 objects, requiring
IDENTICAL prompt sets gives 83 -- and closed by proposing that the choice be priced where it
matters, at the claims rather than at the classes.

Running P4 on that question (this time on EVERY question the round asks, which is R747's own lesson)
turned up something larger than a price. The two counts the deliverable carries were computed under
DIFFERENT RELATIONS:

    R524  `same(a,b): len(ma)==len(mb) and (ma==mb).all() and array_equal(sa,sb)`   FULL OVERLAP
          -> claim row 9: "56 tags are 46 objects"
    R730  `same(A,B): equal on the prompts they SHARE, guard len>=0.5*min`          SUBSET
          -> "93 tags are 81 objects"

And they disagree on a specific class that both computed:
    R524's multi_tag_classes contains  ['coval_core_2bA', 'coval_core_2bB']
    R730's contains                    ['coval_core', 'coval_core_2bA', 'coval_core_2bB']

Same three tags, two rules, two answers. The page presents 46 and 81 as the same kind of quantity.

E1  the object count of each population under each rule, as a 2x2 grid:
        {R524's 56 tags, R730's 93 tags} x {full-overlap, subset}
    Three cells are committed somewhere; the fourth -- 56 tags under the subset rule -- has never

E2  which deliverable claims state an object count that DIFFERS between the two rules.

For E2, IDENTIFIED only for claims that STATE an object count. A claim resting on an object count

--------------------------------------------------------------------------------
WORLDS
--------------------------------------------------------------------------------
A · THE RULE IS COSMETIC AT THE CLAIM LEVEL. The two counts differ in the partition but no
    deliverable claim's stated number moves. The page needs one sentence naming the rule, and
    nothing else changes.
B · THE RULE MOVES A CLAIM. At least one stated object count differs between rules, so the page
    carries a number with a hidden parameter and the affected claims must carry both values.

PREDICTION MATRIX -- deliverable claims whose stated count differs
    A -> 0            B -> >= 1

--------------------------------------------------------------------------------
⛔ THE ARITHMETIC, DERIVED BEFORE MEASURING -- TWO RESULTS ARE FORCED
--------------------------------------------------------------------------------
D1  subset_count <= full_overlap_count, ALWAYS, on the same population. The subset relation is
    strictly weaker: every pair full-overlap merges, subset also merges. So the full-overlap
    partition REFINES the subset one. "The count went up" is therefore not a finding on either
    population; only the SIZE of the gap is.

D2  THE EXTENSION'S OBJECT COUNT CANNOT MOVE. Its five members -- coval_core, topw_k3, topw_k4,
    topw_k6, topw_k8 -- sit in FIVE DIFFERENT classes under R730's subset rule (visible in its
    committed multi_tag_classes: coval_core's class and topw_k4's class are distinct and contain no
    other extension member). A refinement cannot merge what is already separate, so under
    full-overlap they remain five. Registering a prediction about it would be registering algebra.
    It is VERIFIED in code as an assertion, and it is NOT counted as evidence.

So the round's real content is E1's missing cell and E2 -- and the honest possibility that E2
returns ZERO, which would retire the worry rather than confirm it.

--------------------------------------------------------------------------------
KILL -- CONDITIONAL, gated on the controls
--------------------------------------------------------------------------------
if POSITIVE separates the two rules on a synthetic strict-subset pair, and g=0 leaves them agreeing
on a synthetic unequal pair, and NEGATIVE shatters both partitions, and P3 and P4 both reproduce:
        P5 == 0  -> WORLD A. The rule is cosmetic at the claim level; the page needs the rule NAMED
                    and no number changes. The worry R747 raised is retired, and saying so is the

        P5 >= 1  -> WORLD B. Every affected claim carries both values from here on.
else:
        UNVERIFIED. Never OVERTURNED, never CONFIRMED.

--------------------------------------------------------------------------------
CONTROLS
--------------------------------------------------------------------------------
POSITIVE   SYNTHETIC WORLD. Build two arms whose prompt sets are a STRICT SUBSET pair with equal
           values on the shared prompts. The SUBSET rule must merge them; FULL OVERLAP must not.
           BAND, COMPUTED: floor = a rule that merges nothing (0 merges on a known-mergeable input),
           ceiling = a rule that merges everything (1 merge). The two real rules must land on
           OPPOSITE sides of this input, asserted in code -- if they agree here the instrument
           cannot see the distinction it is being used to measure.
g=0        two synthetic arms differing on a shared prompt: BOTH rules must refuse. This is the
           direction that matters -- a subset rule that merges unequal arms would manufacture P1.
NEGATIVE   replace every value vector with distinct noise. Both partitions must shatter to
           n_tags singletons. Excludes "the partition is driven by the tag names".
SHAM       the same operation with the INGREDIENT ABSENT, not inverted. Ingredient = the difference
           in prompt sets. Restrict to the sub-population whose arms ALL share one prompt set; the
           two rules must then agree EXACTLY. If they differ there, overlap is not what separates
           them and D is false.
PLACEBO    each rule against itself on the same population -> exactly 0 disagreeing classes,
           reported as "0 of N" with N printed.
NOISE      no rng except the NEGATIVE control's noise, which is seeded and swept over 3 seeds.
UNIT       instrument unit = a CLASS of tags; claim unit = a STATED NUMBER in the deliverable. NOT
           equal. So E2 is computed by reading stated counts out of the page and comparing them to
           both rules' outputs, never by counting classes and calling it claims.
