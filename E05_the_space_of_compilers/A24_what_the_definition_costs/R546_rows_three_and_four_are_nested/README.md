# R546 · Register rows 3 and 4 are nested — row 3 cannot buy anything alone

**Decision this makes safe:** whether the register's two on-site rows are two pieces of work.

**Estimand:** the logical relation between row 3 (*more ③-any-admissible prompt-responsive
generators*) and row 4 (*a `gen`-like arm ~0.0153 A2 stronger*).

| | |
|---|---|
| ③-any-admissible arms in the census | **25** |
| of those, prompt-responsive | `gen`, `gen_sham`, `promptecho`, `promptecho_sham` |
| of those, clearing ② | **0** |

⭐⭐⭐ **Any arm satisfying row 4 satisfies row 3. An arm satisfying row 3 but NOT row 4 leaves the
extension at 0 — it changes nothing.** The rows are **nested**: one new generator, two bars, and
only the higher bar is load-bearing.

**So the register carries a row that cannot buy anything on its own.** R544/R545 established both
need the same edit (a new `FEWSHOT` or a `--model` flag); this establishes they are **not two
edits**, and that clearing row 3 alone is indistinguishable from doing nothing.
