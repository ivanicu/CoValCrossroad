WHAT HAPPENED, DISCLOSED IN FULL BECAUSE IT IS THE ROUND
   R735 closed by declaring that separating overlap from selection size needs a NEW SELECTION RUN.
   "A wall never checked" is a named failure mode, so I checked it. Satisfaction is stored per
   (prompt, index, letter); I read the letter as the criterion index and joined arms on
   (prompt, index, criterion text). That join reported 89% INCONSISTENCY, which would have meant the
   judge's score depends on which other criteria share the set -- a large finding.
   ⛔ IT WAS MY BUG. corebench/judge_core.py:77 scores ONE criterion per call, so set-dependence is
   impossible by construction. Reading the meta: a k=12 arm has index values 0..11 and letters A..D,
   so the INDEX is the criterion and the LETTER is the response. My join was inverted.
   ⛔⛔ AND MY POSITIVE CONTROL PASSED ON IT -- 0 inconsistent over 15,440 keys -- because the two
   tags I controlled with are ONE OBJECT, so the inversion applied identically to both sides and
   cancelled. That is §4 verbatim: a control that shares the instrument's blind spot confirms the
   instrument and licenses nothing. I quoted that row three rounds ago.

DISCRIMINATING CTRL   ⭐ THE CONTROL THE LAST ONE LACKED. A same-object pair cannot detect an index
                inversion, because the inversion cancels. The control that CAN is the contrast
                itself: run BOTH joins and require the inverted one to return a materially HIGHER
                rate. If the two joins agree, the instrument cannot see the difference and neither
                rate is admissible. band computed: inverted rate must exceed corrected by > 0.10.
POSITIVE CTRL   the same-object pair still required to return exactly 0 under the corrected join --
                necessary, and now explicitly labelled INSUFFICIENT ON ITS OWN.
g=0             an arm joined against itself -> 0 inconsistent, by construction.
NEGATIVE CTRL   permute the criterion TEXTS within each prompt before joining and require the rate to
                jump. excluded world: "the join matches on prompt and response alone, so the
                criterion text is doing no work".
SHAM            join on (prompt, response) with the criterion text DROPPED -- the ingredient absent
                rather than inverted -- and report the rate, which must be high because different
                criteria then collide.
PLACEBO         a key set against itself -> exactly 0.
NOISE FLOOR     R419's measured scoring-only floor of 0.0 on identical criteria is the floor any
                residual must be read against.
