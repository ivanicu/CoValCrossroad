# R1013 · size and its residual are withdrawn — the sham shares them

⚠ **THE DIRECTORY NAME OVERSTATES THE FINDING.** It reads *"no text-only property can be
definitional"*; **this round refuted that sweeping form** with its own measurement. The name is left
alone deliberately (P1's rename trap, R960's collision class) and corrected here.

**THE DECISION THIS MAKES SAFE.** Whether R986's size **residual** — the one property found that
separates `coval_core` from the whole `topw` family — can be a definitional clause. **It cannot: the
sham has it too.**

---

## The candidate, and its death

| arm | residual | in the ②′ extension |
|---|---:|---|
| **`coval_core`** | **43** | in |
| **`coval_core_sham`** | **43** | out |
| `coval_core_2bA` / `_2bB` | 8 | in |
| `gen` / `gen_sham` | 2 / 2 | out |
| every `topw` in the extension | **0** | in |

**Only 6 of 96 arms have a non-zero residual, and they come in arm/sham pairs with identical values.**
The sham's own size distribution is `{2:1, 3:42, 4:925}` — the same 43 non-cap prompts.

⛔ **A property a sham shares cannot distinguish a core from the same criteria misapplied.** So
**size, the size residual and size variability are WITHDRAWN** as candidate clauses.

## ⚠ The sweeping argument was refuted — by this round

I first claimed that **every** text-only property is shared by construction, since a sham is the same
criterion sets re-paired to wrong prompts. Measured over the three arm/sham criteria pairs on disk:

| pair | size structure | text volume |
|---|---|---|
| `promptecho` | same | same |
| `topw_k4` | same | same |
| **`gen`** | same | **differs** — mean_chars 241.0568 vs 240.7169 (~0.14%), and mean_words, mean_unique_criteria |

**Size structure held on all three; text volume did not.** The argument holds **per arm**, is not a
theorem, and **vocabulary and length are NOT withdrawn** — they need their own test. Claiming them
would be the same overreach a second time.

## ⛔⛔ The scope that matters most

**`coval_core`'s own criteria file is not on disk.** The available pairs are `gen`, `promptecho`,
`topw_k4` — so the pairwise comparison runs on arms **other than the instance**. What is measured on
the instance is R986's committed residual: **43 for both core and sham.** That is the candidate
clause's own test, and it is what the withdrawal rests on — not the three-pair table.

## ⭐ What the withdrawal leaves standing

**A2 depends on the pairing and is not shared.** So **definitional content that survives a sham must
read the criteria AND their own prompt together** — which is exactly what clause ② does, and it is a
positive statement about where a definition of "core" can live.

⚠ **R990's non-redundancy is text-only and falls under the same doubt — and is NOT withdrawn here.**
It was never measured on an arm/sham pair. Withdrawing it without that measurement would repeat the
overreach this round just corrected.

## ⚠ Impossible here

**Properties requiring the criteria's semantics** (novelty against the prompt's own rubric, topical
fit) — N/A: they need a model, and a model-dependent property carries a gauge bound this round cannot
pay for.

## Alternatives considered

**Propose the residual as clause ⑤.** Refused the moment the sham's 43 appeared. It would have been
*"the definition describes the instance"* in its purest form — a clause whose only job is to admit the
object it was written from, and which a deliberately corrupted version of that object also satisfies.

**Keep the sweeping "no text-only property" claim and treat `gen` as noise.** Refused: 0.14% is small
but it is a real difference in a quantity that should be identical under the stated construction, and
explaining away the one case that contradicts a derivation is how a derivation becomes a narrative.
