## What was built

`assurance/an_impossibility_names_where_it_would_be_settled.py`. A block declares `SETTLES:` plus one
tag from a **closed set** — HB8 (*if it can be an enum, it may NOT be text*) and R1029 (*store the
field, do not recover it*):

| tag | meaning |
|---|---|
| `IN-RELEASE <object>` | **name** the object inside this release that would settle it |
| `OUT-OF-RELEASE <what>` | it genuinely needs something the release lacks |
| `UNATTACKED` | no claim about possibility is being made |

⚠ **`OUT-OF-RELEASE` is the tag the five falsified lines wrongly deserved**, so it is the one to be
most suspicious of when writing it. **`UNATTACKED` is the honest default and costs one word.**

## Controls

- **POSITIVE (parser)** — five constructed cases with known verdicts: no field → `NO-DECLARATION`;
  invented tag → `INVALID-TAG`; tag naming nothing → `…-NAMES-NOTHING`; valid `IN-RELEASE`; valid
  `UNATTACKED`. **All PASS**, and the gate **refuses to run** if they do not.
  ⚠ These are **constructed** cases and validate the **parser only** — *a parser validated against
  invented blocks is validated against my imagination*, which is exactly why an empty **real**
  population exits 2.
- **NEGATIVE** — empty in-scope population must exit **2**, never 0: verified **before** this round's
  block existed.
- **PLACEBO / NOISE FLOOR / SEEDS / MULTIPLICITY** — **N/A**, stated rather than invented: there is
  no contrast here that must return zero, and the check is exact string structure.

## What it cannot do

**It checks that a declaration EXISTS and is well-formed, never that it is TRUE.** Tagging a
genuinely external limit `IN-RELEASE` passes. **The enum removes the wording loophole, not the
mislabelling one** — the same boundary `register_requirements.py` draws for its own field.

And this round's own `IMPOSSIBLE` block says so in the new format:
`SETTLES: OUT-OF-RELEASE a reader who is not the author` — checking a tag is honest needs someone
without my context, which is **door ③**, not a file in this repository.
